\section{Formatos y serializaci\'on}
\label{sec:formatos}

Para asegurar la interoperabilidad y evitar ambig\"uedades en la interpretaci\'on
de los mensajes, se definen a continuaci\'on los esquemas de persistencia y de
red, la codificaci\'on un\'ivoca de datos y las reglas de validaci\'on.

Todos los valores binarios (nonces, textos cifrados y elementos de grupo serializados)
se codifican mediante \code{base64url} sin relleno (\emph{unpadded}) conforme a la
Secci\'on~5 del RFC~4648 \cite{rfc4648}. Los elementos del grupo \texttt{ristretto255}
se representan estrictamente en su forma can\'onica de 32\,bytes (256 bits)
seg\'un el RFC~9496 \cite{rfc9496}.

\subsection{Codificaci\'on can\'onica y c\'alculo de huellas}
Para prevenir ataques de extensi\'on o ambig\"uedades debidas a textos de longitud
variable:
\begin{enumerate}
\item \textbf{Codificaci\'on inequ\'ivoca de $\mathsf{ctx}$:}
Se compone anteponiendo a cada cadena de texto su longitud en 2 bytes sin signo
(\emph{big-endian}):
\begin{equation}
\mathsf{ctx} = \mathrm{u16}(|\mathit{cat\_id}|)\Vert \mathit{cat\_id} \Vert
\mathrm{u16}(|\mathit{ver}|)\Vert \mathit{ver} \Vert
\mathrm{u16}(|\mathit{group}|)\Vert \mathit{group}
\end{equation}
\item \textbf{Codificaci\'on de $sid$ e \'indice $j$:}
El identificador $sid$ se interpreta como sus 16 bytes binarios nativos
(\code{bytes.fromhex(sid)}). El \'indice $j$ se codifica estrictamente como un
entero sin signo de 32 bits en orden de red (\emph{big-endian}, 4 bytes):
$\mathrm{format\_u32}(j) = j.\mathrm{to\_bytes}(4, \text{'big'})$.
\item \textbf{Diferenciaci\'on de Datos Asociados ($AAD$):}
\begin{align}
AAD_{\mathrm{cat}, j} &= \mathsf{ctx} \Vert \mathrm{format\_u32}(j) \\
AAD_{\mathrm{ot}, j} &= \mathsf{ctx} \Vert sid \Vert \mathrm{format\_u32}(j)
\end{align}
El dato asociado del cat\'alogo protege el registro en reposo; el de la sesi\'on
OT vincula la clave transferida a la sesi\'on espec\'ifica y a la posici\'on $j$.
\item \textbf{C\'alculo de \code{sha256\_root}:}
Se define de forma determinista aplicando SHA-256 sobre la concatenaci\'on en
orden ascendente de los bytes crudos de cada registro del cat\'alogo:
\begin{equation}
\code{sha256\_root} = \mathrm{SHA\text{-}256}\Big(\bigoplus_{j=1}^N (\mathit{nonce}_j \Vert C_j)\Big)
\end{equation}
El cliente verifica esta huella tras descargar \code{catalog.json}; si discrepa,
aborta la ejecuci\'on.
\end{enumerate}

\subsection{Reglas de validaci\'on y rechazo}
\begin{itemize}
\item \textbf{Elementos de grupo mal formados:} Si al decodificar $u$ o $v$ desde
b64url los 32 bytes no corresponden a un punto can\'onico v\'alido de
\texttt{ristretto255} (RFC~9496, Ap\'endice~A.2), la petici\'on es rechazada con
HTTP \code{400 Bad Request}.
\item \textbf{Sesiones duplicadas o expiradas:} Si un $sid$ ya fue consumido o
caduc\'o, el servidor responde con HTTP \code{409 Conflict} o \code{404 Not Found}.
\item \textbf{Versi\'on incompatible:} Si la versi\'on del cat\'alogo no coincide
con la del servidor, se devuelve HTTP \code{422 Unprocessable Entity}.
\item \textbf{Invariancia del mapa \code{record\_id} a \code{idx}:} El mapeo
p\'ublico entre identificador e \'indice no cambia dentro de la misma versi\'on.
\end{itemize}
